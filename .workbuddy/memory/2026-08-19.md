## 关键设计裁决（PK 会议）
创造派 vs 验证派双 Agent 评审：
1. 标记权归工具层（[DREAM] 印工具注入，Agent 不可自补，awaken 拒收无印——防自评权复辟）
2. 预算硬顶+配额并行（超限全废；min_hypotheses 未满不得唤醒）
3. 审计挂 L1 压力级（宁漏报勿误伤）；只杀重复空洞不杀离奇
4. HYPOTHESIS 永不自动升格；INSIGHT 禁入事实层
5. 薪火五步：述笥→锚证→序薪→试燃→传火（收束合法性来自清点完整性非叙事流畅度）
6. 八术人际版不发布（GHM.md 附操控识别防御篇）

## 工程要点
- 此目录**非 git 仓库**（git stash 不可用，误报虚惊一场）
- bundle 由 `npm run generate-bundle` 从 skills/ 扫描生成；category 前缀=目录名前缀
- bundle 的 content 字段=SKILL.md 的 System Prompt 代码块内容（非正文）；测试断言须据 System Prompt 实文
- 全量 npm test 913 项，唯一预存失败：hook-artifact 的 Git Bash polyglot run-hook.cmd 环境测试（与 dream 无关）

## 修复 hook-artifact polyglot bash 分支（步子哥指令）
- 病根：Git Bash `pwd` 输出 MSYS 路径（/c/... 或 /tmp/...），Windows 原生 node 误读为盘符根路径 → hook.js MODULE_NOT_FOUND → exit 1
- 修法：hook-templates.ts 的 RUN_HOOK_CMD bash 分支加 `cygpath -m` 转换（Git Bash/MSYS2/Cygwin 皆有 cygpath；无则退回原逻辑，Linux/macOS 不受影响）
- 连带：distributions/claude-code/hooks/run-hook.cmd 是"单一数据源"一致性测试的镜像副本，改模板必须同步（hook-export.test.ts 校验）——改 hook-templates 后务必 `node -e` 用 build 产物重写该副本
- 修复后全量 913/913 全绿（0 失败），evals 12/12
